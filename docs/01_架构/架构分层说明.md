# 圣殿骑士团3D · 架构分层说明

## 1. 顶层结构

```
圣殿骑士团3D/
├── assets/                  # 资产层：所有美术内容
│   ├── concept/             # 概念设定与参照图
│   ├── models/
│   │   ├── characters/      # 角色模型（.blend 源文件 + .glb 运行文件）
│   │   ├── props/           # 武器、盾、道具
│   │   └── environment/     # 城堡、树木、地形构件
│   ├── materials/           # 材质与配色契约（JSON）
│   ├── textures/            # 贴图
│   └── renders/             # 渲染验收图，不参与游戏运行
├── maps/                    # 地图与关卡数据
├── src/                     # 游戏代码（预留，按五层组织）
│   ├── data/                # 兵种、数值、配置
│   ├── core/                # 玩法内核：规则与状态，不依赖渲染
│   ├── engine/              # 平台层：渲染器、输入、时钟、模型加载
│   ├── view/                # 表现层：场景、单位视图、UI、特效
│   └── app/                 # 编排层：会话、游戏循环、存档
├── site/                    # 离线查看器（静态页，three.js 已 vendored，无构建）
├── tools/                   # 可重复执行的生产脚本（Blender / 站点自检等）
├── tests/                   # 数据、模型与玩法验证
├── docs/                    # 架构与资产管线文档
└── README.md                # 项目入口
```

## 2. 依赖铁律

- `assets/` 只存资产，不含玩法逻辑；模型命名与 `src/data/` 的兵种 ID 对应。
- `maps/` 只描述地图、出生点、环境引用，不直接修改模型或写战斗规则。
- `src/core/` 不依赖 three.js、DOM 或 Blender；胜负与数值只能由内核决定。
- `src/view/` 读取内核状态并显示，不反向决定战斗结果。
- `tools/` 是资产生产线，不属于运行时；游戏运行不执行 Python。
- `assets/renders/` 是验收产物，不作为贴图或模型被游戏加载。
- `site/` 是只读的资产查看器：只从 `assets/` 取 GLB，不写回，也不参与游戏运行时。

## 3. 资产流向

```
concept/ 概念设定
    ↓
tools/build_templar.py 程序化建模
    ↓
models/characters/templar.blend（可编辑源文件）
    ↓ GLB 导出
models/characters/templar.glb（three.js / Godot 可加载）
    ↓
maps/ 引用模型组成战场 → src/engine 加载 → src/view 显示
```

## 4. 改什么，改哪里

| 需求 | 修改位置 |
|---|---|
| 改配色/金属度 | `assets/materials/palette.json` + 建模脚本材质参数 |
| 改角色造型 | `tools/build_templar.py`，或打开 `.blend` 手改 |
| 改兵种数值 | `src/data/`（后续实现） |
| 改地图/出生点 | `maps/` |
| 改战斗规则 | `src/core/`（后续实现） |
| 改光照/相机/UI | `src/view/`（后续实现） |

原则：**模型、地图、数值、规则、表现分开改**，不把任何一类硬编码进另一类。
